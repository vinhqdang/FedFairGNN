# TrustFedGNN: Trustworthy Federated Graph Neural Networks

Reference implementation for the manuscript **"Unifying Fairness Privacy
Robustness and Explainability in Federated Graph Neural Networks for High Stakes
Risk Detection"** (*Springer Discover Artificial Intelligence*, collection
*Trustworthy and Responsible Federated Learning*; under revision).

TrustFedGNN trains a fraud/risk-detection GNN across institutions that cannot
share raw graph data, and is simultaneously **fair**, **differentially
private**, **Byzantine-robust**, **explainable**, and **regulation-aligned**.
Every number and figure in the paper is regenerated from logged runs — nothing
is hand-authored.

## Method

| Component | Where | What it does |
|-----------|-------|--------------|
| **FSER** — Fairness-Sensitive Edge Reweighting | client, in message passing | learnable attention correction that suppresses biased cross-group edges |
| **FTGD** — Fairness-Targeted Gradient Decomposition | client, per step | $(\epsilon,\delta)$-DP for the **released** 2-D demographic-parity statistic (not the whole update) — privacy nearly free vs. full-gradient DP-SGD |
| **BFWA** — Bi-objective Frank–Wolfe Aggregation | server | steers aggregation toward an operator-chosen target $\tau$ on the *reported client* disparity — a surrogate, not a certified bound on the global model's DPD; `robust_bfwa` adds Byzantine screening |
| **Trust layer** | evaluation | MC-dropout uncertainty + calibration, FSER attention explanations, composite trust score, sustainability, EU AI Act / NIST RMF compliance + model card |

## Datasets (downloaded on demand, cached under `data/raw/`)

| Dataset | Nodes | Sensitive attr. | Domain |
|---------|------:|-----------------|--------|
| German  | 1,000 | gender | credit risk |
| Credit  | 30,000 | age | default |
| Bail    | 18,876 | race | recidivism |
| Pokec-z/n | ~67k | region | social |
| **Elliptic** | **203,769** | time period (proxy) | **crypto AML** |

Real fairness benchmarks (German/Credit/Bail via NIFTY, Pokec via FairGNN) plus
the large-scale Elliptic Bitcoin graph; a documented synthetic testbed supports
controlled bias-injection ablations.

## Install

```bash
pip install torch --index-url https://download.pytorch.org/whl/cpu   # CPU wheels
pip install -r requirements.txt
```

Everything runs on CPU (Elliptic's 204k nodes train at ~1 s/epoch).

## Quick start

```bash
# single run
python -m experiments.run_experiment --method fedfairgnn --dataset bail --seed 0

# full experiment matrix (resumable; logs to results/)
python -m experiments.run_matrix --study main,ablation,privacy,robustness

# regenerate all manuscript tables + figures from logged results
python -m experiments.report
python -m experiments.trust_eval        # calibration/sustainability + model card
```

Methods available to `--method`: `fedavg-gcn`, `fedavg-gat`, `fairgnn`,
`fairsin`, `fairfed`, `qffl`, `f2gnn`, `favgnn`, `fdp-fair`, `fairgfl`,
`fedgraphfair`, `puffle`, `fedfact`, `popets-fairfed`, `dp-fedavg`,
`fedfairgnn`, `fedfairgnn-nodp`, `ours-robust`, and ablations. (`fedfb` is
also implemented but is not part of the reported comparison — see the note in
Section 3.2 of the paper.) Aggregators: `fedavg`, `bfwa`,
`krum`, `multikrum`, `median`, `trimmed_mean`, `robust_bfwa`. Attacks: `none`,
`label_flip`, `gaussian`, `scaling`, `sign_flip`, `ipm`, `alie`,
`fairness_poison`.

> **Why `--method fedfairgnn` selects TrustFedGNN.** The preset *keys* keep the
> pre-rename name because `exp_name` is baked into every already-logged
> `run_id`; renaming them would orphan completed runs rather than relabel them.
> The model dispatch string and every user-facing name were renamed. See
> [the papers](#papers) for the rename, and `experiments/methods.py` for the note.

## Reproducibility

- **Every run is fully specified by a serialised `ExperimentConfig`** (`src/config.py`),
  and every dataset is public and downloaded on demand — so any number in the
  paper can be reproduced end to end from this repository alone.
- All randomness is seeded; results are reported as mean ± std over seeds.
- Privacy accounting, metrics, and aggregation rules are unit-tested (CI on push).
- `experiments/report.py` regenerates every table and figure in the paper from a
  run log at `results/summary.jsonl`.

**What is and is not in this repository.** The code, the configurations, and the
generated tables (`manuscript/tables/`) and figures (`manuscript/figures/`) are
all here. The raw per-run logs (`results/`, several GB across the full matrix)
are *not* committed; they are available from the corresponding author on request,
or can be regenerated with:

```bash
python -m experiments.run_matrix --study main,ablation,privacy,robustness
```

### What changed between the two

The conference paper introduced FSER, FTGD and BFWA, evaluated on three
fraud-detection graphs (YelpChi, Amazon, Elliptic) with a single `K=3` client
configuration. The journal article extends it substantially, and this repository
implements the extended framework — renamed **FedFairGNN → TrustFedGNN** to
reflect the wider scope:

| | Conference (FedFairGNN) | Journal (TrustFedGNN) |
|---|---|---|
| Datasets | 3 fraud graphs, `K=3` | 5 fairness benchmarks + a 2.4M-node scalability study |
| Baselines | small set | 15, including five 2025–2026 methods reimplemented here |
| Robustness | — | `robust_bfwa` + a new fairness-poisoning attack |
| Privacy evidence | guarantee only | + adversarial attribute-inference evaluation |
| Statistics | — | multi-seed paired Wilcoxon significance tests |
| Trust layer | — | uncertainty, attention audits, trust score, sustainability, EU AI Act / NIST RMF mapping |

### Scope of the claims

Three qualifications are stated in the paper and repeated here so the code is not
over-read:

- **FTGD's DP guarantee covers the *released fairness statistic*,** not the whole
  transmitted update — FSER and the fairness-gradient masks still touch `s`.
- **BFWA's τ is an operator target on *reported client* disparity,** a surrogate
  for — not a certified bound on — the deployed model's DPD.
- **FSER needs the protected attribute at inference,** for both endpoints of every
  attended edge, which carries real legal and governance obligations for a
  deployer (§6 of the paper).
